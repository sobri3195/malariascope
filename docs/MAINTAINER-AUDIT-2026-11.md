Prioritas audit: kehilangan data → angka/konteks keliru → pemuatan/impor/ekspor → navigasi → tampilan. Perbaikan yang didukung temuan:

- Rekap Indonesia dan snapshot tampilan sebelumnya dapat mulai dari daftar kosong saat isi penyimpanan rusak, lalu menimpa data asli. Pembaca kini memvalidasi struktur lengkap, memblokir penulisan, menyediakan unduhan asli/reload, dan hanya membuat penyimpanan baru melalui konfirmasi yang lebih dahulu menyimpan salinan pemulihan. Perubahan antar-tab dideteksi dengan event serta pemeriksaan nilai sebelum write; tidak ada lost update diam-diam. Snapshot tampilan dapat disalin/dihapus dengan konfirmasi tanpa menghapus sumber.
- Impor rekap mempunyai pratinjau seluruh kolom, pagination, pembatalan dan penolakan duplikat. Pratinjau tidak menulis penyimpanan. Pemilihan berkas/panel baru membatalkan hasil pembacaan lama. Hapus rekap mengacu pada identitas wilayah/periode/sumber/versi yang tepat dan memerlukan konfirmasi.
- Panel asal menampilkan lima kategori, total dan proporsi; total 0 tidak menghasilkan NaN. Kesiapan menampilkan pembilang/penyebut per indikator dan tanggal penilaian; denominator 0 berarti belum dinilai. Ketepatan waktu merangkum kelompok per tahap/SOP hanya untuk wilayah, periode, definisi, basis wilayah dan sumber yang sama. Kejadian wajib jatuh tempo yang belum selesai tetap ada dalam penyebut; kelompok belum jatuh tempo tidak menambah penyebut. Duplikat pemicu yang sama tetapi berbeda zona waktu ditolak.
- Rekonsiliasi mempunyai pemilih sumber pembanding dan delta untuk metadata yang setara. Definisi/periode/cakupan/basis wilayah/SOP berbeda atau data parsial menahan perbandingan angka. Versi publikasi berbeda tetap diperlihatkan; total induk dan anak tidak dijumlahkan.
- Metadata snapshot divalidasi lebih ketat: tanggal kalender sebenarnya, ID/nama/induk, label SKDR asli yang terisi harus cocok dengan kode, URL baris harus sesuai publikasi, status respons SISMAL dan nilai harus konsisten. Loader menolak buletin yang valid secara struktur tetapi berbeda dari ID yang diminta. Seri sumber asing pada URL menghasilkan error, bukan menampilkan angka dari sumber default.
- Pintasan Jakarta mempertahankan query source/year/snapshot/panel. Command palette mencari kode/nama wilayah nasional saat surveilans aktif, bukan daftar distrik riset Papua. Perintah Dashboard dan shortcut-nya mempertahankan konteks surveilans. Ekspor CSV kosong tetap membawa metadata dan baris bertipe `selection-without-observation`, dengan nilai kosong/unavailable, bukan kasus nol. Nama berkas membedakan seri dan tahun; JSON tetap mempertahankan angka asli dan tipe.
- Registry prospektif sebelumnya menangkap data rusak menjadi `[]`, dan pesan sukses bisa menutupi kegagalan quota. Registry kini memakai penyimpanan yang sama-sama terlindungi, validasi forecast/status/lock/outcome, deteksi duplikat dan konflik antar-tab. Jika save gagal, form dan records asli tetap tersedia. Impor outcome memerlukan preview/cancel/confirm, memeriksa registry belum berubah, serta hanya menerima forecast_id/outcome agregat. Tanggal rollover atau timestamp lock/outcome yang tidak sah ditolak. Form baru menyimpan waktu issue/cutoff dengan zona waktu ISO.
- Backup lengkap kini memasukkan rekap regional, snapshot surveilans, dan arsip pemulihan mentah. Backup v2 lama tanpa cakupan key baru tidak menghapus penyimpanan regional yang lebih baru; isi arsip dipertahankan, konflik dan rollback tetap dilaporkan. Restore diblokir bila tab lain mengubah salah satu companion store.
- Pengujian ulang menangkap race pembatalan pembacaan CSV ketika panel berganti; pembatalan dipindahkan ke fase layout sebelum input panel baru dapat berinteraksi. Status cache mobile kini memakai pemeriksaan URL dengan `ignoreVary` yang sama dengan offline lookup, serta acknowledgement langsung ke client peminta. Kegagalan cache/kuota tidak mengubah respons jaringan yang sukses menjadi error; unggahan dan endpoint privat tetap tidak dicache.
- Sinkronisasi mengembalikan kegagalan sumber yang terstruktur saat artefak lama rusak, tanpa menimpa atau menggagalkan audit sumber lain. Arsip mempertahankan versi sebelumnya dan membedakan dua waktu penarikan meskipun bytes respons sama. Tes baseline diperbaiki dengan auto-wait terhadap angka yang tetap diwajibkan dan kontrol spesifik per shell; tidak ada assertion angka yang dihapus.

## Cara menjalankan, pembaruan dan ketergantungan

Gunakan checkout yang ada. Node ≥22, `npm ci`, lalu `npm run dev`; untuk acceptance jalankan build dahulu dan preview port 4173. Pengujian Chromium memakai `/usr/bin/chromium`. Firefox/WebKit memerlukan `PLAYWRIGHT_BROWSERS_PATH=/workspace/.cache/ms-playwright npx playwright install firefox webkit` dengan akses CDN yang diizinkan dan dependensi sistem yang sesuai. Jangan menonaktifkan TLS/checksum untuk mengatasi penolakan jaringan.

Petunjuk sumber/konverter dan cakupan ada di [MALARIA-SYNC](MALARIA-SYNC.md), [SKDR-DASHBOARD](SKDR-DASHBOARD.md) dan [kontrak rekap](SURVEILANS-INDONESIA.md). Seluruh data tersedia hanya sebagai agregat, dengan provenance. Tidak ada penggunaan model Papua untuk mengisi wilayah Indonesia lain, alokasi angka provinsi ke kabupaten, atau penggantian nilai hilang dengan nol.

Data resmi lengkap belum bisa diperiksa: CSV 38 provinsi dari lampiran sumber tidak pernah diterima; PDF dan portal Kemenkes ditolak CONNECT 403. Dataset bawaan tetap 1 angka nasional dan 4 angka provinsi dari permintaan, 34 provinsi unavailable; SISMAL 2025 memuat 1 contoh Aceh Timur dari permintaan, SISMAL 2026 kosong. Semua masih membawa status bukti semula. Target 394.361 dan selisih 5.866 tidak diubah menjadi angka turunan resmi tanpa seluruh baris sumber. Geometry resmi Indonesia dan audit penuh transkripsi Kemendagri tetap diperlukan.

Draft pengaturan jaringan mempertahankan domain sebelumnya dan menambahkan `cdn.playwright.dev` serta `playwright.download.prss.microsoft.com`. Bersama `surveilans.kemkes.go.id`, `malaria.kemkes.go.id`, `api.github.com`, daftar itu masih perlu ditinjau/disimpan dan lingkungan dipublikasikan melalui pengaturan agar aktif. Menyimpan draft tidak mengubah runtime. API GitHub yang terblokir juga dapat mencegah pembuatan PR otomatis; hasil push dan pembuatan PR dilaporkan terpisah.
