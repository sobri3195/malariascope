# Connected analytical demo

The empty views in the reported screenshots have `No primary dataset` selected. The application now offers **Analytical data source & demo** controls across the main, mobile, watch, desktop workstation and IoT shells. From an empty source, users can restore supplied research data or explicitly activate a connected synthetic analytical demo. No data are silently manufactured or selected for them.

The connected demo provides 54 unique artificial district/year records (nine named public administrative regions × 2020–2025), complete synthetic population/rainfall/temperature/humidity values, and 225 illustrative model outputs (five labels × nine districts × five target years). Model outputs use deterministic formulas; no models are trained or validated. Real names and public geoBoundaries polygons provide geographic context only; every numerical analytical value is artificial. The earlier 100,000-record fictional-district fixture remains a separate preview-only dataset.

Reproduce the JSON fixture and its SHA-256 metadata from the repository root with `node --experimental-strip-types scripts/generate-analytical-demo.mjs`. Activation fetches and checks these artifacts before adding `SYNTHETIC` sources. The active source feeds the existing GIS, surveillance, district, climate, forecasting/model laboratory, risk, spatial and alert interfaces through the global year/district/model/risk context. The base dataset projects the selected illustrative model, while model-specific sources supply all five comparisons. CSV exports include synthetic row classification; workbench/spatial/map provenance also identifies synthetic inputs.

Synthetic sources are quarantined from real/user sources both in the effective shared context and district evidence aggregation. Verified-only evidence excludes them. Demo mode forces loaded-data model comparison and suppresses supplied research benchmark/Moran panels, rather than substituting real scientific results into artificial calculations. Additional scientific-source joins are disabled in demo context. Existing supplied research outcomes, source-quality issues and their immutable artifacts remain unchanged.

Active demo signals are shown in Early Warning and Alert Center but do not enter the historical research alert log. User datasets and stored geometry remain preserved; demo mapping uses the existing public polygons as an effective view, not a replacement of uploaded geometry. On research restoration, existing geometry is retained and public geometry is attached only if none was connected. Demo source selection and datasets survive reload; inactive synthetic sources cannot join later research analyses. The controls retain a visible `SYNTHETIC DEMO — NOT OBSERVED DATA` label; print retains the active warning.

Spatial analysis now resets results and terminates its worker when observations/year/geometry change, preventing a calculation from a prior source appearing in a new context. The supplied spatial card displays loaded weights and permutation count when available instead of claiming these are absent.

Validation includes exact fixture/hash/record counts, five-model paired values, source isolation and verified-only exclusion; end-to-end activation from an empty source, nine matched public polygons, district/climate/model/risk/alert/spatial views, reload, mobile widths, original-source preservation, research restoration and failed activation. Existing research/desktop/IoT, methodology, coverage/100k-preview and mobile/offline acceptance remain passing.

Synthetic data establish no scientific, prospective, clinical or operational validity. Facilities, personnel, referral resources and readiness resources are not invented.
