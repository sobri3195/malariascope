# Project rules

MALARIASCOPE is a retrospective malaria research prototype. This handbook describes contributor and agent responsibilities; it does not install autonomous agents or create a multi-agent runtime.

## Scope and authority

Follow the user's requested scope, repository instructions and existing authorization. Preserve unrelated changes. Read the relevant modules before editing; do not rebuild the application from scratch for a targeted request. A request to open a pull request authorizes preparing, checking and publishing that branch, not merging it. External messaging and operational deployment require explicit authorization.

## Scientific integrity

- Keep supplied study evidence, imported observations, predictions, derived calculations, synthetic demos and scenarios distinct.
- A valid schema or checksum does not establish independent scientific verification.
- Never invent missing observations, denominators, model outputs, trained artifacts or readiness resources.
- Preserve provenance, units, periods, missingness, uncertainty and known limitations in UI and exports.
- Explanations and alerts must follow explicit deterministic rules. Do not produce autonomous clinical or military instructions.
- Use only public, authorized, aggregated data. Do not ingest private patient records or sensitive operational locations.

## Completion

Make focused, reviewable changes. Run checks appropriate to the affected behavior, report failures honestly, and link the pull request. Follow [workflow](15-workflow.md), [coding](17-coding-standard.md) and [testing](18-testing-standard.md) standards.
